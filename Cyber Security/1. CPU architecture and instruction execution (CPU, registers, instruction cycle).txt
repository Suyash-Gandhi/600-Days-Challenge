# 1. CPU Architecture and Instruction Execution
Topics: CPU, Registers, Instruction Cycle  
Recommended Depth: Medium — Cybersecurity Fundamentals

## 1. Introduction

The Central Processing Unit (CPU) is the primary processing component of a computer. It executes program instructions, performs arithmetic and logical operations, and coordinates the activities of other hardware components.

For cybersecurity, understanding CPU architecture is important because it helps you understand:

- How programs execute at the hardware level.
- How operating systems interact with hardware.
- How processes execute instructions.
- How memory addresses and registers work.
- How buffer overflows and other memory corruption vulnerabilities occur.
- How debuggers, disassemblers, and reverse-engineering tools work.
- How malware executes instructions and interacts with the operating system.

For example, when you execute a program in Linux, the CPU processes its machine instructions while the operating system manages its execution environment, memory, and access to system resources.

Let's understand how this works.

---

# 2. CPU Architecture

CPU architecture describes the organization of a processor and how it executes instructions.

A simplified CPU consists of several important components:

1. Arithmetic Logic Unit (ALU)
2. Control Unit (CU)
3. Registers
4. Instruction decoder
5. Cache memory
6. Internal data paths and buses



Let's examine each component.

## 2.1 Arithmetic Logic Unit (ALU)

The ALU performs arithmetic and logical operations.

### Arithmetic operations
- Addition
- Subtraction
- Increment
- Decrement

### Logical operations
- AND
- OR
- XOR
- NOT
- Comparisons

For example, consider this instruction:

```asm
ADD RAX, RBX
```

In x86-64 assembly, this instruction adds the value in `RBX` to the value in `RAX` and stores the result in `RAX`.

Conceptually:

```text
RAX = RAX + RBX
```

If:

```text
RAX = 10
RBX = 20
```

After execution:

```text
RAX = 30
```

The ALU performs the addition, while the CPU's control logic coordinates the operation.

Cybersecurity relevance: Understanding ALU operations helps you interpret assembly instructions during reverse engineering and malware analysis.

---

## 2.2 Control Unit (CU)

The Control Unit coordinates instruction execution.

Its responsibilities include:

- Directing the fetching of instructions.
- Coordinating instruction decoding.
- Controlling data movement between registers and other components.
- Signaling which operations the CPU should perform.
- Coordinating execution with other processor components.

For example, when the CPU executes an instruction to load data from memory, the control logic coordinates the operation so the data reaches the appropriate register.

Think of the Control Unit as the coordinator of CPU operations.

It does not independently perform every calculation. Instead, it directs the components responsible for those operations.

---

## 2.3 Instruction Decoder

Programs ultimately execute as machine instructions encoded in binary.

Consider a simplified representation:

```text
Machine code → Instruction decoder → CPU operations
```

The instruction decoder interprets an instruction's encoding to determine what operation it represents and which operands it uses.

For example, an instruction might specify:

```asm
MOV RAX, RBX
```

The decoder identifies the operation and its operands. The CPU then carries out the corresponding data movement.

The exact implementation differs across processor architectures.

Cybersecurity relevance: Disassemblers such as Ghidra and tools such as GDB help you inspect machine instructions in a more readable assembly representation.

---

## 2.4 Registers

Registers are small, extremely fast storage locations inside the CPU.

They hold values that the processor needs while executing instructions.

For example:

```asm
MOV RAX, 10
MOV RBX, 20
ADD RAX, RBX
```

The CPU performs the following operations:

1. Places `10` in `RAX`.
2. Places `20` in `RBX`.
3. Adds the values.
4. Stores `30` in `RAX`.

Registers are particularly important because machine instructions frequently operate directly on them.

We will examine register types in Section 3.

---

## 2.5 Cache Memory

Cache is small, fast memory located on or near the CPU that stores copies of data and instructions likely to be needed again.

Modern processors commonly have multiple cache levels:

| Cache | General characteristics |
|---|---|
| L1 | Smallest and usually fastest |
| L2 | Larger than L1, generally slower |
| L3 | Often larger and shared among multiple CPU cores |

The CPU checks the relevant cache hierarchy when accessing instructions or data. If the required data is not present in a cache, it may need to retrieve it from a lower level of the memory hierarchy.

Cache helps reduce the time spent waiting for data.

Cybersecurity relevance: Cache behavior can sometimes leak information through timing differences. Attacks such as Spectre exploit microarchitectural behavior, including speculative execution, to infer information that should not be directly accessible.

You do not need to understand cache-coherence protocols or advanced cache attacks yet.

# 3. CPU Registers

Registers are one of the most important concepts to understand before studying assembly language, debugging, or reverse engineering.

## 3.1 What Is a Register?

A register is a storage location inside the CPU used to hold a value temporarily.

Consider a program performing this calculation:

```c
int a = 10;
int b = 20;
int c = a + b;
```

At the machine level, the compiler may arrange for the values to be held in registers, on the stack, or elsewhere in memory.

A simplified assembly representation could be:

```asm
MOV RAX, 10
MOV RBX, 20
ADD RAX, RBX
```

After execution:

```text
RAX = 30
RBX = 20
```

This is a simplified illustration. Actual compiler output depends on the compiler, optimization settings, and target architecture.

### Why are registers important?

Registers allow the CPU to access working values without repeatedly retrieving them from main memory.

However, registers are limited in number. Programs therefore use a combination of registers, cache, and RAM.

---

## 3.2 General-Purpose Registers

General-purpose registers can hold values used in different kinds of operations.

Consider the x86-64 architecture, commonly used in desktop computers and servers.

Some important 64-bit general-purpose registers are:

| Register | Common role or convention |
|---|---|
| RAX | Often used for return values and arithmetic |
| RBX | General-purpose; preserved across calls in common calling conventions |
| RCX | General-purpose; also used for counters and specific instruction operands |
| RDX | General-purpose; also used for arithmetic and function arguments |
| RSI | General-purpose; commonly used for a source pointer and function arguments |
| RDI | General-purpose; commonly used for a destination pointer and function arguments |
| RBP | Often used as a frame pointer |
| RSP | Stack pointer |
| R8–R15 | Additional general-purpose registers |

These registers have conventional uses, but many can hold different kinds of values depending on the instruction and calling convention.

For example:

```asm
MOV RAX, 100
MOV RBX, 50
SUB RAX, RBX
```

Result:

```text
RAX = 50
RBX = 50
```

The `MOV` instructions transfer values, and `SUB` subtracts the second operand from the first.

### Important distinction

Register names and conventions differ between processor architectures.

For example:

- x86-64 uses registers such as `RAX`, `RBX`, and `RSP`.
- AArch64 uses registers such as `X0`, `X1`, and `SP`.

The underlying concepts are similar, but the instruction sets and conventions differ.

---

## 3.3 Instruction Pointer

The instruction pointer identifies the address associated with the next instruction to be executed.

On x86-64, it is called RIP.

On AArch64, the corresponding program-counter concept is represented by `PC`.

For example, imagine instructions located at these addresses:

```text
Address       Instruction

0x1000        MOV RAX, 10
0x1007        MOV RBX, 20
0x100E        ADD RAX, RBX
0x1011        RET
```

The instruction pointer helps the processor determine where instruction fetching should proceed.

The example addresses are illustrative. Actual instruction lengths and addresses depend on the machine code.

Normally, execution proceeds through instructions in sequence. However, jumps, branches, function calls, returns, interrupts, and exceptions can change the flow of execution.

For example:

```asm
JMP 0x1011
```

This instruction transfers control to the specified destination.

Cybersecurity relevance: Understanding the instruction pointer helps when analyzing crashes, tracing program execution, debugging suspicious executables, and investigating control-flow hijacking.

---

## 3.4 Stack Pointer

The stack is a region of memory commonly used for function calls, local variables, saved registers, and return addresses.

The stack pointer identifies the current stack position according to the processor architecture's conventions.

On x86-64, the stack pointer register is `RSP`.

Consider a simplified function call:

```c
void example() {
    int x = 10;
}
```

Depending on the compiler and optimization settings, the function's local variable may be stored in a register or in stack memory.

The stack is also used to support function calls and returns.

For example, on x86-64, a conventional `CALL` instruction saves a return address on the stack before transferring control to the called function. A corresponding `RET` instruction uses the saved return address to resume execution.

Cybersecurity relevance: Incorrect memory handling involving stack-based buffers can cause stack buffer overflows. Under certain conditions, these can corrupt nearby data or interfere with control flow.

Do not assume that every stack buffer overflow allows code execution. Exploitability depends on the program, processor, operating system, and enabled protections.

---

## 3.5 Flags Register

The flags register contains status information about certain CPU operations.

On x86-64, the flags are represented within `RFLAGS`.

Important flags include:

| Flag | Meaning |
|---|---|
| ZF — Zero Flag | Indicates that an operation produced a zero result |
| CF — Carry Flag | Records carry or borrow information for relevant operations |
| SF — Sign Flag | Reflects the sign bit of a result |
| OF — Overflow Flag | Records signed arithmetic overflow for relevant operations |

For example:

```asm
MOV RAX, 10
SUB RAX, 10
```

The subtraction produces zero, so the Zero Flag is set.

A subsequent conditional jump can use this information:

```asm
JZ equal
```

`JZ` transfers execution to `equal` if the Zero Flag is set.

This allows programs to implement conditional behavior at the machine-instruction level.

Cybersecurity relevance: Flags are useful when analyzing conditional branches, authentication checks, comparisons, and program control flow in assembly.

---

## 3.6 How Registers Work Together

Consider this C code:

```c
int a = 5;
int b = 3;
int result = a + b;
```

A simplified assembly illustration is:

```asm
MOV RAX, 5
MOV RBX, 3
ADD RAX, RBX
```

Execution:

| Step | Instruction | RAX | RBX |
|---|---|---:|---:|
| 1 | `MOV RAX, 5` | 5 | — |
| 2 | `MOV RBX, 3` | 5 | 3 |
| 3 | `ADD RAX, RBX` | 8 | 3 |

The result is `8`, stored in `RAX`.

Notice that the CPU can perform the calculation using values already held in registers.

This is a simplified illustration rather than a guarantee of the exact instructions a compiler will generate.

# 4. Instruction Execution

The CPU executes machine instructions through a sequence of operations commonly explained using the instruction cycle.

The simplified instruction cycle consists of:

1. Fetch
2. Decode
3. Execute
4. Store or write back the result
5. Update the instruction pointer as appropriate

Real processors are more complex: they use techniques such as pipelining, out-of-order execution, and speculative execution. Nevertheless, the simplified cycle is an excellent starting point.



## 4.1 Fetch

The CPU obtains the next instruction from the instruction stream.

The instruction pointer identifies where instruction fetching should proceed.

Conceptually:

```text
Instruction address → Instruction fetch → CPU
```

For example, suppose the next instruction is:

```asm
ADD RAX, RBX
```

The processor fetches its machine-code representation.

Modern processors may fetch multiple instructions and use instruction caches, so the actual hardware process is more complex than this simplified description.

---

## 4.2 Decode

The CPU interprets the fetched instruction.

For example:

```asm
ADD RAX, RBX
```

The processor determines that the instruction performs addition using the specified registers.

The instruction encoding identifies the operation and operands.

---

## 4.3 Execute

The processor performs the operation.

Suppose:

```text
RAX = 10
RBX = 20
```

Instruction:

```asm
ADD RAX, RBX
```

The result is:

```text
RAX = 30
```

The processor's execution units perform the required operation.

Different instructions use different execution resources. An addition may use an arithmetic execution unit, while a memory-load instruction involves the memory-access machinery.

---

## 4.4 Store or Write Back

If the instruction produces a result, the processor writes that result to its destination.

For our addition example:

```text
RAX = 30
```

The destination is a register, so the result is written to `RAX`.

Other instructions may write results to memory or update processor flags.

Not every instruction produces a conventional data result.

---

## 4.5 Update the Instruction Pointer

The processor determines which instruction should execute next.

For sequential execution, the instruction pointer advances to the next instruction.

For a branch or jump, execution may continue at a different address.

For example:

```asm
MOV RAX, 10
JMP target
MOV RAX, 20
target:
MOV RBX, 30
```

If the jump is taken, the instruction `MOV RAX, 20` is skipped.

This is the foundation of control flow in machine code.

---

# 5. Complete Instruction Execution Example

Let's combine the concepts.

Consider this assembly program:

```asm
MOV RAX, 5
MOV RBX, 3
ADD RAX, RBX
SUB RAX, 2
```

Its purpose is to calculate:

\[
(5 + 3) - 2 = 6
\]

### Step-by-step execution

Instruction 1

```asm
MOV RAX, 5
```

The value `5` is placed in `RAX`.

```text
RAX = 5
```

Instruction 2

```asm
MOV RBX, 3
```

The value `3` is placed in `RBX`.

```text
RAX = 5
RBX = 3
```

Instruction 3

```asm
ADD RAX, RBX
```

The processor adds the value in `RBX` to the value in `RAX`.

```text
RAX = 8
RBX = 3
```

Instruction 4

```asm
SUB RAX, 2
```

The processor subtracts `2` from `RAX`.

```text
RAX = 6
RBX = 3
```

Final result:

```text
RAX = 6
```

This example demonstrates how instructions manipulate register values sequentially.

# 6. How Programs Reach the CPU

Understanding CPU execution also requires understanding the relationship between source code, machine code, and the operating system.

Consider a C program:

```c
#include <stdio.h>

int main(void) {
    int a = 5;
    int b = 3;

    printf("%d\n", a + b);

    return 0;
}
```

The source code is not ordinarily executed directly by the CPU.

Instead, a compiler translates it into machine code that the processor can execute.

A simplified view is:

```text
C source code
      |
      v
Compiler
      |
      v
Executable containing machine code
      |
      v
Operating system loads the program
      |
      v
CPU executes its instructions
      |
      v
Program produces output
```

The compiler may optimize the code, meaning the final machine instructions might not correspond one-to-one with the original source statements.

The operating system also manages the process's execution environment, including virtual memory, permissions, and system resources.

### What happens when you run a program in Linux?

For a typical native executable:

1. You execute a command in the shell.
2. The shell initiates program execution.
3. The operating system creates or establishes a process execution context.
4. The executable is loaded and its memory mappings are established.
5. The CPU begins executing the program's instructions.
6. When the program needs an operating-system service, it may use a system call.
7. The operating system handles the request and returns control to the program when appropriate.

The exact details depend on the executable format, operating system, runtime, and program.

Important distinction: The CPU executes instructions, while the operating system manages processes and controls access to system resources.

# 7. Why CPU Architecture Matters in Cybersecurity

These concepts are particularly valuable in reverse engineering, vulnerability research, and malware analysis.

## 7.1 Reverse Engineering

Reverse engineering involves examining a compiled program to understand its behavior.

Tools such as Ghidra and GDB can help you inspect assembly instructions, registers, memory, and execution flow.

For example, you might encounter:

```asm
CMP RAX, 0
JZ failure
```

You can interpret this as:

1. Compare the value in `RAX` with zero.
2. Update the relevant flags.
3. Jump to `failure` if the Zero Flag is set.

This understanding helps you reconstruct program logic.

## 7.2 Buffer Overflow Vulnerabilities

A buffer overflow occurs when a program writes beyond the intended boundaries of a buffer.

Depending on the circumstances, this may corrupt adjacent data or affect control flow.

To understand stack-based buffer overflows, you need to understand:

- Stack memory
- Stack pointers
- Return addresses
- Function calls and returns
- Memory addresses
- Registers such as `RSP` and `RIP`

These concepts provide the foundation for studying memory corruption safely in controlled lab environments.

## 7.3 Malware Analysis

Malware analysts frequently inspect machine instructions to determine what a suspicious program does.

For example, assembly instructions may reveal:

- Conditional branches used to select execution paths.
- Function calls associated with file or network operations.
- Arithmetic used to decode embedded data.
- Loops used to process files or memory.
- System-call transitions or calls to operating-system APIs.

The instructions alone may not establish the program's intent, but they provide evidence that can be combined with dynamic analysis and other observations.

## 7.4 Exploit Mitigation

Several operating-system and hardware security mechanisms are easier to understand once you know how the CPU executes instructions.

| Security mechanism | Why CPU knowledge helps |
|---|---|
| DEP/NX | Helps explain why executing instructions from non-executable memory can be prevented |
| ASLR | Helps explain why memory addresses may differ between executions |
| Stack canaries | Helps explain how certain stack-corruption attempts are detected |
| Control-flow protections | Helps explain how some unintended control-flow transfers can be restricted |
| Speculative-execution mitigations | Helps explain why CPU microarchitectural behavior matters for security |

These mechanisms have different implementations and limitations. They reduce particular risks rather than guaranteeing that a program is secure.

# 8. Practical Lab: Observe CPU Registers

You can practice these concepts using Linux and GDB.

### Step 1: Install the tools

On Ubuntu or a similar Debian-based distribution:

```bash
sudo apt update
sudo apt install build-essential gdb
```

### Step 2: Create a C program

Save this as `cpu_demo.c`:

```c
#include <stdio.h>

int main(void) {
    int a = 5;
    int b = 3;
    int result = a + b;

    printf("Result: %d\n", result);

    return 0;
}
```

### Step 3: Compile with debugging information

```bash
gcc -g -O0 cpu_demo.c -o cpu_demo
```

The `-g` option includes debugging information, while `-O0` disables most compiler optimizations to make the example easier to inspect.

### Step 4: Start GDB

```bash
gdb ./cpu_demo
```

Inside GDB, set a breakpoint:

```gdb
break main
run
```

### Step 5: Examine the assembly

```gdb
disassemble main
```

This displays the machine instructions associated with `main`.

The exact instructions depend on your compiler, architecture, and build environment.

### Step 6: Inspect registers

```gdb
info registers
```

On an x86-64 machine, you may see registers such as:

```text
rax
rbx
rcx
rdx
rsi
rdi
rsp
rbp
rip
```

These values change as the program executes.

### Step 7: Step through instructions

```gdb
display/i $pc
si
```

Here:

- `display/i $pc` displays the instruction at the current program counter.
- `si` executes one machine instruction and stops again.

Repeat `si` and inspect the registers to observe how instruction execution changes the processor state.

Note: A C expression such as `a + b` may compile into several instructions or be optimized differently in another build. Use the actual disassembly rather than assuming the compiler will generate a particular sequence.

For more information, see the official documentation for GDB at [GNU GDB documentation](https://sourceware.org/gdb/documentation/?utm_source=chatgpt.com).
