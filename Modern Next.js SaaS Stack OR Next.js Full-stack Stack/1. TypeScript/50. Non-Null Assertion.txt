# 50. Non-Null Assertion (`!`) in TypeScript

The non-null assertion operator `!` tells TypeScript:

> “I know this value is not `null` or `undefined. Trust me.”

It is mainly used when TypeScript isn't able to figure out something that you know is definitely true.

---

## 1. The problem

Suppose you have:

```ts
let username: string | undefined;

username = "Suyash";

console.log(username.length);
```

TypeScript may complain:

```text
Object is possibly 'undefined'.
```

Why?

Because the type says:

```ts
string | undefined
```

TypeScript thinks:

> "Maybe `username` is undefined."

Even though you know that you've assigned `"Suyash"` before using it.

---

## 2. Using `!`

You can write:

```ts
let username: string | undefined;

username = "Suyash";

console.log(username!.length);
```

The `!` means:

```ts
username!
```

> "TypeScript, I guarantee this isn't `null` or `undefined`."

So TypeScript treats it approximately as:

```ts
string
```

instead of:

```ts
string | undefined
```

---

# 3. Very important: `!` does NOT change the runtime value

This is the most important thing to understand.

Consider:

```ts
let username: string | undefined;

console.log(username!.length);
```

The `!` doesn't magically make `username` a string.

At runtime, `!` disappears.

The JavaScript is essentially:

```js
console.log(username.length);
```

Since `username` is actually `undefined`, you'll get a runtime error.

So:

```ts
value!
```

means:

> "Don't check this for me, I promise it's not null/undefined."

It does not mean:

> "Make this value non-null."

---

# 4. Why does TypeScript need this?

Consider the DOM:

```ts
const button = document.getElementById("submit");
```

TypeScript gives `button` the type:

```ts
HTMLElement | null
```

because technically this element might not exist.

You might know that your HTML definitely contains:

```html
<button id="submit">Submit</button>
```

So you could write:

```ts
const button = document.getElementById("submit")!;

button.addEventListener("click", () => {
    console.log("Clicked");
});
```

The `!` tells TypeScript:

> "I know this element exists."

Without it:

```ts
const button = document.getElementById("submit");

button.addEventListener("click", () => {
    console.log("Clicked");
});
```

TypeScript complains because `button` could be `null`.

---

# 5. `!` vs checking properly

Usually, this is safer:

```ts
const button = document.getElementById("submit");

if (button) {
    button.addEventListener("click", () => {
        console.log("Clicked");
    });
}
```

Now you're actually checking at runtime.

Compare:

### Non-null assertion

```ts
const button = document.getElementById("submit")!;

button.addEventListener("click", handler);
```

You're saying:

> "Trust me."

### Proper check

```ts
const button = document.getElementById("submit");

if (button) {
    button.addEventListener("click", handler);
}
```

You're saying:

> "Let's verify."

The second approach is generally safer.

---

# 6. Another common example

Imagine:

```ts
interface User {
    name: string;
}

let user: User | undefined;
```

You could write:

```ts
console.log(user!.name);
```

You're telling TypeScript:

```text
user is definitely defined
```

But if you're wrong:

```ts
user = undefined;
```

then:

```ts
user!.name
```

will crash at runtime.

---

# 7. Don't confuse `!` with `?`

These look similar but do completely different things.

### Optional chaining `?.`

```ts
user?.name
```

means:

> "If `user` exists, get `name`; otherwise give me `undefined`."

### Non-null assertion `!`

```ts
user!.name
```

means:

> "I guarantee `user` exists. Let me access `name`."

So:

```ts
user?.name
```

is defensive.

```ts
user!.name
```

is a promise to TypeScript.

---

# 8. Don't confuse it with `!` in boolean expressions

There's another completely different use of `!`:

```ts
const isLoggedIn = false;

if (!isLoggedIn) {
    console.log("Please log in");
}
```

Here `!` means logical NOT.

But:

```ts
user!.name
```

is the non-null assertion operator.

Same symbol, different meaning.

---

# 9. The mental model

Think of it this way:

```ts
value!
```

means:

```text
TypeScript:
"Could this be undefined?"

You:
"No. I know something you don't."

TypeScript:
"Okay, I'll assume it's defined."
```

But TypeScript doesn't verify your claim.

That's why `!` should be used carefully.

---

## When should you use it?

Good use:

```ts
const element = document.getElementById("app")!;
```

when you know from the application structure that `#app` must exist.

Bad use:

```ts
const user = getUser();

console.log(user!.name);
```

when `getUser()` genuinely might return `undefined`.

Instead:

```ts
if (user) {
    console.log(user.name);
}
```

---

## The one sentence to remember

> Non-null assertion `!` tells TypeScript “this is definitely not `null` or `undefined,” but it does nothing to protect you at runtime.

So if you remember only this:

```ts
value!
```

= “Trust me, TypeScript.”

Not:

```ts
value!
```

= “Make this value exist.”
