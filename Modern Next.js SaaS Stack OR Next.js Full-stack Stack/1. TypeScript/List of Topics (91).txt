# PHASE 10 — Production Type Safety

84. `unknown` in Error Handling
85. Exhaustiveness Checking with `never`
86. Strict Mode
87. `strictNullChecks`
88. Avoiding `any`
89. Avoiding Unnecessary Type Assertions
90. TypeScript Types vs Runtime Validation
91. Type-Safe API Design

#90 is particularly important.

TypeScript:

```ts
type User = {
  name: string;
  age: number;
};
```

does not guarantee that incoming HTTP data actually has that structure.

That's why you'll eventually use runtime validation with things such as Zod or NestJS DTO validation.

# Learn Through React/Next.js Projects

Don't treat these as another TypeScript theory phase.

Learn them naturally when they appear:

 Component props
 `children`
 Callback props
 `useState`
 `useRef`
 Events
 Forms
 Context
 Custom hooks
 API responses
 Fetch responses
 Generic components
 Server Components
 Client Components
 Page props
 Dynamic route params
 Search params
 Server Actions
 Route Handlers
 Environment variables

For example, when building:

```tsx
type UserCardProps = {
  name: string;
  age: number;
};

function UserCard({ name, age }: UserCardProps) {
  return <div>{name}</div>;
}
```

you're learning props + object types + React TypeScript simultaneously. There's little benefit in treating each as an isolated chapter.
