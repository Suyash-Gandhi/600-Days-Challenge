# 3. `.ts` vs `.tsx`

The difference is very simple:

> `.ts` = TypeScript without JSX
> `.tsx` = TypeScript with JSX

## 1. `.ts` Files

Use `.ts` when the file contains normal TypeScript code and no JSX/React markup.

```ts
const name: string = "Suyash";
const age: number = 22;

function add(a: number, b: number): number {
  return a + b;
}
```

Common `.ts` files include utilities, services, API logic, types, configuration, and backend code.

For example:

```text
utils.ts
types.ts
api.ts
auth.service.ts
user.controller.ts
```

In a NestJS backend, you'll mostly work with `.ts` files.

---

## 2. `.tsx` Files

Use `.tsx` when TypeScript code contains JSX.

```tsx
function Welcome() {
  const name: string = "Suyash";

  return <h1>Hello, {name}</h1>;
}

export default Welcome;
```

This part:

```tsx
<h1>Hello, {name}</h1>
```

is JSX, so the file needs to be `.tsx`.

You'll mainly see `.tsx` in React and Next.js components.

```text
Navbar.tsx
Button.tsx
LoginForm.tsx
page.tsx
layout.tsx
```

---

## 3. Why Can't We Just Use `.ts`?

Suppose you write:

```ts
function App() {
  return <h1>Hello</h1>;
}
```

TypeScript needs to know that `<h1>` is JSX syntax, rather than ordinary TypeScript syntax.

Therefore:

```text
App.ts   ❌
App.tsx  ✅
```

---

## 4. Easy Rule to Remember

| File contains    | Extension |
| ---------------- | --------- |
| TypeScript only  | `.ts`     |
| TypeScript + JSX | `.tsx`    |

For example:

```text
React component with JSX → .tsx
Utility function          → .ts
Type definitions          → .ts
NestJS controller         → .ts
Next.js page              → .tsx
Next.js React component   → .tsx
```

One important detail: React itself doesn't automatically mean `.tsx`. If a file has no JSX, it can still be `.ts`.

### Interview answer

`.ts` files contain standard TypeScript code, while `.tsx` files allow TypeScript together with JSX syntax. `.tsx` is therefore commonly used for React and Next.js components that return JSX.
