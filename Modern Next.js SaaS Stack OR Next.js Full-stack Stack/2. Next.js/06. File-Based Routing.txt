# 6. File-Based Routing in Next.js

One of the biggest advantages of Next.js is File-Based Routing.

Instead of manually configuring routes like in React Router, Next.js automatically creates routes based on your folder and file structure.

---

## Why File-Based Routing?

In React, you typically write:

```jsx
<Route path="/about" element={<About />} />
<Route path="/contact" element={<Contact />} />
```

As the application grows, route management becomes larger and harder to maintain.

In Next.js:

```plaintext
app/
 ├── page.js
 ├── about/
 │    └── page.js
 └── contact/
      └── page.js
```

Routes are automatically generated.

```plaintext
/          -> Home Page
/about     -> About Page
/contact   -> Contact Page
```

No route configuration required.

---

## App Router Structure

The modern Next.js App Router uses the `app` directory.

```plaintext
app/
 ├── page.js
 ├── about/
 │    └── page.js
 ├── services/
 │    └── page.js
 └── contact/
      └── page.js
```

Each folder represents a URL segment.

---

## Basic Example

### Home Page

```jsx
// app/page.js

export default function Home() {
  return <h1>Home Page</h1>;
}
```

URL:

```plaintext
/
```

---

### About Page

```jsx
// app/about/page.js

export default function About() {
  return <h1>About Page</h1>;
}
```

URL:

```plaintext
/about
```

---

### Contact Page

```jsx
// app/contact/page.js

export default function Contact() {
  return <h1>Contact Page</h1>;
}
```

URL:

```plaintext
/contact
```

## Nested Routes

Folders inside folders create nested routes.

```plaintext
app/
 └── blog/
      ├── page.js
      └── post/
           └── page.js
```

Generated URLs:

```plaintext
/blog
/blog/post
```

Example:

```jsx
// app/blog/post/page.js

export default function Post() {
  return <h1>Blog Post</h1>;
}
```

---

## Dynamic Routes

Used when URLs contain variable values.

Example:

```plaintext
/blog/1
/blog/2
/blog/100
```

Structure:

```plaintext
app/
 └── blog/
      └── [id]/
           └── page.js
```

The square brackets create a dynamic parameter.

```jsx
export default function BlogPost({ params }) {
  return <h1>Post ID: {params.id}</h1>;
}
```

URLs:

```plaintext
/blog/1
/blog/2
/blog/99
```

---

## Multiple Dynamic Parameters

```plaintext
app/
 └── users/
      └── [userId]/
           └── posts/
                └── [postId]/
                     └── page.js
```

URL:

```plaintext
/users/10/posts/5
```

Access:

```jsx
export default function Page({ params }) {
  return (
    <>
      <p>User: {params.userId}</p>
      <p>Post: {params.postId}</p>
    </>
  );
}
```

---

## Catch-All Routes

Capture multiple URL segments.

Structure:

```plaintext
app/
 └── docs/
      └── [...slug]/
           └── page.js
```

Matches:

```plaintext
/docs/react
/docs/react/hooks
/docs/react/hooks/useeffect
```

Example:

```jsx
export default function Docs({ params }) {
  return <pre>{JSON.stringify(params.slug)}</pre>;
}
```

Output:

```js
["react", "hooks", "useeffect"]
```

---

## Optional Catch-All Routes

```plaintext
app/
 └── docs/
      └── [[...slug]]/
           └── page.js
```

Matches:

```plaintext
/docs
/docs/react
/docs/react/hooks
```

---

## Route Groups

Used to organize files without affecting URLs.

```plaintext
app/
 ├── (marketing)/
 │    ├── about/
 │    │    └── page.js
 │    └── contact/
 │         └── page.js
```

URLs remain:

```plaintext
/about
/contact
```

The `(marketing)` folder is ignored in the URL.

---

## Private Folders

Folders beginning with `_` are used for organization.

```plaintext
app/
 ├── _components/
 ├── _utils/
```

These do not create routes.

---

## Linking Between Pages

Use Next.js Link component.

```jsx
import Link from "next/link";

export default function Home() {
  return (
    <>
      <Link href="/about">About</Link>
      <Link href="/contact">Contact</Link>
    </>
  );
}
```

Benefits:

 Client-side navigation
 Faster page transitions
 Automatic prefetching

## Route Special Files

| File         | Purpose              |
| ------------ | -------------------- |
| page.js      | Route UI             |
| layout.js    | Shared layout        |
| loading.js   | Loading UI           |
| error.js     | Error UI             |
| not-found.js | 404 Page             |
| route.js     | API Route            |
| template.js  | Re-renderable layout |

Example:

```plaintext
app/
 ├── page.js
 ├── layout.js
 ├── loading.js
 ├── error.js
 └── not-found.js
```

---

## React Router vs Next.js Routing

| React Router           | Next.js            |
| ---------------------- | ------------------ |
| Manual route setup     | Automatic          |
| Requires configuration | Folder-based       |
| Extra package          | Built-in           |
| Client-side only       | Supports SSR & SSG |
| More boilerplate       | Less boilerplate   |

---

## Interview Questions

### 1. What is File-Based Routing?

A routing system where routes are automatically created from folders and files.

---

### 2. How do you create a route in Next.js?

Create a folder and add a `page.js` file inside it.

---

### 3. How do dynamic routes work?

Using square brackets:

```plaintext
[id]
```

---

### 4. Difference between `[...slug]` and `[[...slug]]`?

 `[...slug]` → Requires at least one segment.
 `[[...slug]]` → Can also match the base route.

---

### 5. What is the purpose of Route Groups?

To organize routes without changing URL structure.

---

### Key Takeaway

Next.js routing is based on folders and files.
Create a folder → add `page.js` → route is automatically available. Dynamic routes use `[param]`, nested folders create nested URLs, and special files like `layout.js` and `loading.js` add powerful routing features with minimal configuration.
