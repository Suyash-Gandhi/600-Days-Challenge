# 7. Layouts in Next.js (App Router)

Layouts are one of the most important features of the App Router.

A Layout is a UI component that wraps pages and remains persistent while navigating between routes.

Instead of repeating the same Navbar, Sidebar, Footer, etc. on every page, you place them inside a layout.

---

## Why Layouts Exist

Without layouts:

```jsx
export default function HomePage() {
  return (
    <>
      <Navbar />
      <h1>Home</h1>
      <Footer />
    </>
  );
}
```

```jsx
export default function AboutPage() {
  return (
    <>
      <Navbar />
      <h1>About</h1>
      <Footer />
    </>
  );
}
```

You repeat the same code everywhere.

With layouts:

```jsx
export default function Layout({ children }) {
  return (
    <>
      <Navbar />
      {children}
      <Footer />
    </>
  );
}
```

Every page automatically gets the Navbar and Footer.

---

# Root Layout

Every Next.js App Router project must have:

```bash
app/layout.js
```

Example:

```jsx
export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        {children}
      </body>
    </html>
  );
}
```

The `children` prop represents the current page.

---

## Project Structure

```bash
app
│
├── layout.js
├── page.js
├── about
│   └── page.js
```

### layout.js

```jsx
export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        <nav>Navbar</nav>

        {children}

        <footer>Footer</footer>
      </body>
    </html>
  );
}
```

### page.js

```jsx
export default function HomePage() {
  return <h1>Home Page</h1>;
}
```

### about/page.js

```jsx
export default function AboutPage() {
  return <h1>About Page</h1>;
}
```

Result:

```
Navbar
Home Page
Footer
```

and

```
Navbar
About Page
Footer
```

# How Layout Rendering Works

When visiting:

```bash
/
```

Next.js renders:

```jsx
<RootLayout>
  <HomePage />
</RootLayout>
```

When visiting:

```bash
/about
```

Next.js renders:

```jsx
<RootLayout>
  <AboutPage />
</RootLayout>
```

# Real-World Layout Example

Most applications use:

```jsx
export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        <Navbar />

        <main>
          {children}
        </main>

        <Footer />
      </body>
    </html>
  );
}
```

Common items inside layouts:

 Navbar
 Footer
 Sidebar
 Theme Provider
 Authentication Provider
 Redux Provider
 Global Modals

---

# Layout Persistence

One major benefit:

Layouts do not re-render during navigation if they remain active.

Example:

```bash
/dashboard/profile
```

→ User clicks

```bash
/dashboard/settings
```

Navbar and Sidebar stay mounted.

Only page content changes.

This makes navigation faster and preserves state.

Example:

```jsx
<input placeholder="Search..." />
```

If it's inside a layout, its state can remain while navigating.

---

# Accessing Children

The `children` prop contains the page being rendered.

```jsx
export default function Layout({ children }) {
  return (
    <div>
      <Sidebar />

      <main>{children}</main>
    </div>
  );
}
```

---

# Difference Between Layout and Page

| Layout            | Page                       |
| ----------------- | -------------------------- |
| Wraps pages       | Represents route content   |
| Persistent        | Changes when route changes |
| Receives children | Doesn't receive children   |
| Shared UI         | Route-specific UI          |

Example:

```jsx
// layout.js
<Navbar />
{children}
```

```jsx
// page.js
<h1>Dashboard</h1>
```

# Interview Questions

### What is a Layout in Next.js?

A component that wraps pages and provides shared UI across multiple routes.

---

### Why use Layouts?

To avoid repeating common UI such as Navbar, Footer, Sidebar, Providers, etc.

---

### What is the purpose of `children`?

It represents the page or nested route being rendered inside the layout.

---

### Does a layout re-render on navigation?

Generally no. Layouts persist while navigating between routes that share the same layout.

---

### Is `app/layout.js` required?

Yes. Every App Router application must have a root layout.
